UI/UX

The interface adopts a bifurcated design strategy tailored to distinct user roles. For the respondent (student), the system prioritizes a frictionless, "eyes-free" experience, utilizing voice-driven interaction to eliminate the cognitive load of text-based input. Conversely, the administrative interface (teacher) provides a robust suite of configuration tools. This includes granular control over avatar aesthetics and linguistic parameters, alongside sophisticated scraping and data-export utilities that streamline the lifecycle of questionnaire management and response analysis.

Functionality

The final implementation successfully addresses the complete spectrum of mandatory requirements outlined in our technical specifications. Rigorous iterative testing has confirmed a high degree of functional reliability, the system consistently performs as intended under various user scenarios, with no critical defects identified during the final evaluation phase.

Stability

System stability is underpinned by a comprehensive testing framework encompassing unit and integration tests across both the C# application core and the Python orchestration layer. By maintaining high code coverage and validating all API inter-dependencies, we have ensured a resilient architecture. This rigorous approach to quality assurance provides a high level of confidence for public-facing deployment and long-term operational uptime.

Efficiency

The application is engineered for high performance, particularly regarding the local execution of Large Language Models (LLMs). By utilizing quantized models, we significantly mitigate the primary computational burden. The surrounding C# and Python logic layers introduce negligible overhead, ensuring that the system's intelligence and conversational flow remain fluid and responsive even on consumer-grade hardware.

Compatibility

While optimized for Windows environments, the application possesses inherent cross-platform extensibility through the Uno Platform. While initial development versions supported macOS, resources were strategically reallocated to prioritize core functional depth. To maximize hardware utility, we have implemented GPU-accelerated optimizations. While mobile support is currently constrained by LLM hardware requirements, the architecture remains poised for future adaptation as edge computing capabilities evolve.

Maintainability

Adhering to strict software engineering paradigms, the system utilizes the Model-View-ViewModel (MVVM) design pattern to ensure a clean separation of concerns. Maintainability is further bolstered by a modular folder hierarchy, consistent naming conventions, and an isolated testing project to prevent environment pollution. The Python integration layer is designed with modularity as a core tenet, facilitating effortless updates to the underlying AI orchestration.

Project Management

The development lifecycle was governed by a structured communication protocol involving synchronous physical meetings and virtual collaboration via Microsoft Teams. We employed an agile-inspired goal allocation strategy to ensure consistent progress. Version control and documentation were meticulously managed via GitHub, utilizing a rigorous pull-request workflow and transparent commit history to maintain a high standard of professional accountability.

Customisable Background

In the current application, the avatar view is limited to a plain black background, with no assets other than the avatar itself. Future versions of the application could allow the user to add custom backgrounds to add colour or match the context of the questionnaire. For example, a questionnaire meant for students could use a classroom backdrop.

Voice Synthesis

Our application allows for 3D models scanned using Avaturn.me to be used as avatars but currently only pre-set Kokoro TTS voices can be used. If support were added for a TTS with voice cloning functionality, it would be possible to create avatars that not only look but also sound like the intended person. This could be useful in applications such as SEND schools, where a student may be more comfortable answering questions if the interviewer has the appearance of a family member or teacher.

Metahuman Avatars

This prototype utilises Unreal Engine’s MetaHuman and Nvidia's audio2face to produce photorealistic avatars. The option for high fidelity avatars was a requested feature in our user research, and this implementation serves as a proof of concept. However, the performance requirements were substantial, and audio2face is only supported on Nvidia GPUs, which limits accessibility. For these reasons, this feature was not integrated into the main application, but it demonstrates the potential for future iterations to include ultra-realistic avatar options for users with high-end hardware.


Different Model Sources e.g. Foundry Local

Currently we are using a Llamafile for local LLM inferencing. This works effectively but the LLamafile has to be included in the packaged application, which adds ~3 GB to the file size. Integration with Foundry Local would mean that our application could be distributed in a more lightweight way and integrate more tightly with the Windows ecosystem.

Sign Language Support

A key success of our application was the support for multilingual input to help facilitate communication across language barriers. However, AvatarForms currently only supports voice and text input. If paired with a camera and an existing sign language recognition library, our avatar would be able to interpret sign language to interview individuals with speech issues.
