Appendices

Additional project information.

1. Creating Interview Sessions

From the home page, click Upload Questionnaire.

On the Create Questionnaire Page, paste in your Microsoft Forms or Google Forms links in the designated textbox.

The questions will be extracted and you will be able to add, edit, or delete them. Click Create Questionnaire to generate the interview session.

2. Starting an interview

From the home page, click on any questionnaire from the questionnaire list.

Once in the Questionnaire Detail page. Click on Continue to Avatar.

This is where you have your interview session.

3. Configure Avatar, Language, and Voice

Choose an avatar, language, and voice profile that matches your interview context. You can also check runtime messages in the console and adjust settings when needed.

4. Manage Questionnaires from Dashboard

Use the Dashboard to review available questionnaires, access controls, and adjust settings for active workflows.

5. View Responses

After interviews are completed, open the responses list to see all submitted entries for a questionnaire.

6. View Response Details

Select a response from the list to inspect its full details, including each recorded answer.

7. Add Custom Avatars

Use Avaturn to generate a custom avatar model. Make sure to select the Type-2 model.

Customise the avatar appearance until it matches your preference.

Download the final avatar with animation for use in the application.

Click Browse in Settings to locate the downloaded avatar files on your device.

Upload Avatar to import the selected files into AvatarForms.

Select Avatar to make your newly imported model active for interviews.

AvatarForms README

AvatarForms

AvatarForms is a Windows application for conversion of digital forms into 3D avatars with a fully local AI interview pipeline.

In many contexts, from education to industry to healthcare, crucial information is collected through static, online forms. However, questions on digital forms are rigid, often requiring answers in specific formats or assuming users are implicitly aware of context. For many people with accessibility needs, these limitations mean that filling out digital forms can be difficult or unintuitive.

AvatarForms aims to help solve this issue by offering an alternative. A digital form can easy be converted to a real-time 3D avatar, that asks poses questions in natural conversation, asks clarifying questions and followups when needed, then accurately records the information gathered as if the user had filled out the form themselves.

Project Structure

.
├── AvatarFormsApp/    # Backend (.NET 10), Frontend (WinUI), Database (SQLite).
├── Backend/           # Python AI agent orchestration layer with APIs (HTTP + WebSocket)
├── Backend-Test/      # Pytest test cases for Python Backend code
├── Evaluation/        # DeepEval LLM Agent Evaluation Framework (scripts + test cases)
├── HeadTTS/           # Open-sourced JavaScript TTS solution by @met4citizen
├── .gitignore         # Git ignore configuration
└── README.MD          # This file

The application copies Backend/**/* and HeadTTS/**/* into build output and manages services within the app.

Requirements

  1. Visual Studio 2022 or newer (with Windows App SDK/WinUI workload) or VS Code + .NET tooling
  2. .NET 10 SDK
  3. Windows 10/11 SDK 10.0.19041.0 or newer
  4. Python 3.x
  5. A .llamafile model placed in Backend/ (Qwen3_4B_Q6_K is recommended)

Note

"Enable long paths" option must be enabled to overcome Windows 260-character limit for file paths, which NuGet packages often break.

Option A: Admin PowerShell

New-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force

Option B: Windows Settings

  1. Navigate to Settings > System > Advanced.
  2. Make sure the "Enable long paths" option is enabled.

Setup

  1. Clone the repository.
  2. From the repository root:
cd Backend
python -m venv env
.\env\Scripts\activate
pip install -r requirements.txt
  1. Compile the Python into an executable:
pyinstaller main.spec
  1. Ensure at least one .llamafile exists in Backend/. Qwen3_4B_Q6_K is recommended. Can be downloaded from Hugging Face: https://huggingface.co/mozilla-ai/Qwen3-4B-llamafile/tree/main.

How To Run

From repository root, build the solution:

dotnet build .\AvatarFormsApp\AvatarFormsApp.sln

Then run from Visual Studio or CLI:

dotnet run --project .\AvatarFormsApp\AvatarFormsApp\AvatarFormsApp.csproj -f net10.0-windows10.0.19041.0

You can also use workspace tasks:

  • build
  • publish
  • watch

Runtime

When you start an interview flow in the app:

  • LlamafileProcessService starts the .llamafile server on port 8081.
  • PythonProcessService starts the Python backend using the compiled Backend/dist/main/main.exe.
  • ResponseAPIService starts the response API server for response collection on port 5000.
  • QuestionnaireAPIService sends in questionnaire data to the questionnaire API server started in api.py on port 8882.
  • The Python backend initialises WebSocket API for real-time speech relay between the Python agent orchestration layer and HeadTTS (3D avatar rendering + TTS layer) on port 8083.
  • Avatar is loaded through WebView2.

Running Tests

C# Tests

Open the outer AvatarFormsApp folder in powershell, and run:

.\run-tests.ps1

Then html testing report will popup.

Python Backend Tests

Ensure packages in both Backend\requirements.txt and Backend-Test\test_requirements.txt are installed to the environment.

Open the Backend-Test folder in the console, and run all test cases with:

pytest

Specific test files can be run with:

pytest test_x.py

Code coverage stats can be viewed by running:

pytest --cov=..\Backend

DeepEval Agent Evaluation

Running the Evaluation

The DeepEval evaluation is currently set up to use gpt-5-mini as the judge LLM, so requires an OPENAI API key.

Set the environment variables:

OPENAI_API_KEY=key here
DEEPEVAL_RESULTS_FOLDER=C:\path\to\results\folder

Run the llamafile in the console with flags --ctx-size 2048 --ngl 9999, noting down the port is starts running on.

Open the Evaluation folder in the console, and run:

python eval.py --port 8081

(replacing the port with the llamafile port)

This will run tests for all 3 agents by default.

To test individual agents, you can use the flags: talker, evaluator, summariser

E.g.

python eval.py --port 8081 --evaluator

Test cases can be viewed or modified in test_cases.py.

Viewing Results

The evaluation results will be displayed in the console, and saved in json format to the DEEPEVAL_RESULTS_FOLDER specified.

Example evaluations run previously have been saved to Evaluation\results.

To view the results graphically, run:

python display.py example_json_file

You can optionally specify a path to save the visualation with the flag --save path\to\save

Traces of agent calls are saved to Evaluation\agent_evaluation_logs, where the prompts and outputs of requests for each agent can be viewed for observability.

Troubleshooting

  • No AI model starts: Verify a *.llamafile exists in Backend.
  • Python backend fails: Verify Backend\env\Scripts\python.exe exists and packages are installed from requirements.txt.
  • Build/path issues on Windows: Enable long paths and restore NuGet packages.
  • Web avatar does not render: Ensure WebView2 runtime is installed and HeadTTS files are present in output.

GDPR Statement

This section describes how AvatarForms handles personal data under the UK GDPR. For project use, AvatarForms operates primarily as a Data Processor, processing form response data on behalf of the form owner/controller.

1. Scope of Processing

AvatarForms processes questionnaire response data entered during interviews. The exact personal data categories depend on the content of each source form (for example, free-text responses and selected options).

2. Local-Only Processing

All processing is performed locally on the user's device. Data does not leave the running device as part of normal operation. Local AI components and frameworks (including Llamafile, OpenVINO, and local TTS tooling) are used without cloud transfer by default.

3. Storage and Retention

Data is stored locally in project/application files and retained until manual deletion by the user or administrator. No fixed automatic retention period is enforced in the current implementation.

4. International Transfers and Third Parties

No routine transfers outside the UK/EU are intended in the local configuration. No external cloud analytics or hosted LLM service is required for core operation.

5. Data Subject Rights

Where applicable, data subjects may exercise their UK GDPR rights, including:

  • Right of access
  • Right to rectification
  • Right to erasure
  • Right to restrict processing
  • Right to data portability
  • Right to object

6. Contact

For data protection queries or rights requests, contact: muaz.mujahid.24@ucl.ac.uk

You may also raise concerns with the UK Information Commissioner's Office (ICO) if you believe personal data has been handled unlawfully.

Privacy Policy

Effective date: 25 March 2026

This Privacy Policy explains how AvatarForms handles personal data for end users of the application.

1. What Data We Process

AvatarForms processes form and interview response content provided by users. The exact data depends on the form questions configured by the form owner/controller.

2. Lawful Basis

Processing is based on consent. By proceeding with data entry and interview submission, users consent to processing of their response data for the intended form purpose.

3. How Data Is Processed

Data is processed locally on the device running AvatarForms. Local AI components may be used to support interview and response workflows. Under the standard local setup, data is not sent to external cloud services.

4. Storage and Retention

Data is stored locally in application/project files and retained until manually deleted by the user or administrator.

5. Cookies, Tracking, and Telemetry

AvatarForms does not use cookies, advertising trackers, or analytics telemetry in its standard local configuration.

6. Children and Sensitive Data

AvatarForms is not intended for children without appropriate supervision and legal basis. Special category data (for example health, biometric, or other sensitive personal data) should not be collected unless explicitly required and lawfully managed by the responsible controller.

7. Your Rights

Where applicable, users can request access, rectification, erasure, restriction, portability, and objection in line with UK GDPR rights.

8. Security

We apply reasonable technical and organisational safeguards for a local-first application setup. However, no method of storage or processing can be guaranteed to be completely secure.
