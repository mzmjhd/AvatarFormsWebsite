Research

This section details the research and prototypes during project development.

Earliest prototype

This approach was made before it was known that we are developing a C# windows application. It was entirely in python. The form scraper scraps an online form, then an AI model engages in conversation through the terminal. Afterwards the answers are output into the online form through an automatic form filler.

Techniques learned

Form scrapper is a very useful feature developed in this prototype which was put into the final product. Since the scrapper is what "connects" the application with an online forms. This prototype also familiarized us with local AI.

Reason for improvement

This prototype was too crude, relying on the terminal rather than an actual user interface. Also, it can only do one form at a time which is too reliant on the online form.

AI control flow prototype

We tried to use n8n to better format the AI flow. The AI outputs JSON that contains two variables, one for if the answer is satisfiable, and one for the actual AI output text.


This then continues for every question. At the end, a table of the user answer to each question was output.

Techniques learned

Familiarized us with the logic and flow of the conversation and AI evaluation loop.

Reason for improvement

The JSON approach was fragile especially when carried over long conversations or when the model used was small. Since this approach relies on the AI model to output the correct JSON variable names.


It was also unclear how we would implement n8n in the C# application.

Conversation prototype

This prototype looks very similar to the avatar page in the final product. The major difference is the method for lipsync and text to speech method. This prototype uses the native speech engine and used a word by word lipsync method that made the C# app instruct the mouth animation of the avatar following the voice output of the operating system.


This prototype showed a high potential for multilingual support and lowering computational cost since it uses the native speech engine.

Techniques learned

This prototype is actually the predecessor of the current final product, because it was the first time we achieved verbal conversation with the AI for form filling. Various functions still remain, such as method of finding the python environment, microphone input, textbox...

Reason for improvement

Due to the way that C# app instructs the mouth animation which is telling the mouth animation to end early when it knows the word has already been output, the mouth animation maybe viewed as jittery at times. The current headTTS approach plays the pre-aligned mouth animation and voice at the same time which was smoother. The windows native speech engine's english voice was also too robotic.

Future prototype

This prototype is very minimal and have not been integrated with the application yet. It is using unreal engine's Metahuman which are very realistic and looks better than the current Talkinghead 3D avatars. Metahuman can also express emotions which would be perfect for imitating a real conversation.


This prototype showed a high potential for realistic avatars, however it is very difficult to implement it into the application due to the unreal engine constraint and computational cost. It could be reserved for future development.
