Research

Details the research and prototypes during project development.

Typebot

Open Source Conversational Forms Automation Integrations

Typebot is a form builder designed around conversational flows instead of static fields. It demonstrates how step-by-step dialogue can reduce abandonment and improve completion quality.

This is relevant to AvatarForms because it validates the same interaction principle: collecting structured data through guided, natural interaction rather than traditional long-form entry.

Reference

GitHub: baptisteArno/typebot.io
Website: typebot.io

Formbricks

Open Source Surveys and Forms Self-hostable

Formbricks is an open-source platform for surveys and form-style data collection with product-friendly analytics and deployment flexibility.

It is useful as a benchmark for AvatarForms in areas such as reliability, deployment options, and collection workflows, while highlighting the unique value of avatar-led, voice-assisted completion.

Reference

GitHub: formbricks/formbricks
Website: formbricks.com

Technology Review Overview

Prototype-led Comparative Evaluation Production-focused

The final AvatarForms architecture was selected through iterative prototyping and evaluation across three major technical directions: Python-based form automation, n8n conversation orchestration, and native speech-engine lip-sync.

The cards below summarize what each approach enabled, what it taught us, and why specific elements were either retained or replaced in the production build.

Model and Runtime Evaluation

We tested multiple local-model families and quantization levels across Qwen and Gemma variants, with a focus on conversational reliability, latency, and answer quality during multi-turn form completion.

After benchmarking practical usability under desktop constraints, we selected Qwen-3B Q6_K as the strongest tradeoff between performance and reliability. It consistently produced stable responses while remaining responsive enough for real-time user interaction.

We also evaluated Foundry Local as part of runtime experimentation. While it offers strong operational value for broader scaling and managed workflows, the client requirement for fully self-contained deployment led us to adopt llamafiles for the current release. For future growth scenarios, Foundry Local remains a strong option to revisit.

Python Online Form Scraper and Filler

This earliest prototype was implemented entirely in Python. It extracted online form fields, captured answers through an AI-assisted terminal conversation, and injected responses back into forms through automated filling logic.

The strongest outcome was technical validation of the extraction-and-fill workflow, which later became a foundational integration in the final system. It also provided practical experience with local model orchestration and prompt-loop control.

Reason for improvement

The prototype remained terminal-centric, constrained to narrow single-form assumptions, and unsuitable for scalable end-user interaction without a robust desktop UI and stronger workflow abstraction.

AI Orchestration Framework

We evaluated n8n as an orchestration layer for a structured AI decision loop where each field generated a JSON payload with validation state and output. This provided clear step-by-step control, visibility, and fast prototyping for workflow iteration.

We also tested LangChain, which offered useful building blocks for prompt chaining, memory patterns, retrievers, and tool-driven flows. It was effective for experimentation but still added abstraction and operational overhead for our desktop-specific constraints.

Based on these findings, we implemented a custom orchestration framework tailored to AvatarForms. This gave us tighter control over reliability, fallback behavior, and runtime performance. The full design is documented in the Implementation page.

Reason for improvement

Strict JSON-schema dependence reduced resilience with smaller local models, and integration overhead with a native C# application increased complexity beyond what was justified for production.

Native Speech Engine Lip-sync Prototype

This prototype synchronized avatar mouth movement with system-generated speech via native Windows voice output and viseme mapping. It offered broad language support and low compute overhead.

It established core production patterns, including microphone handling, desktop event coordination, and the initial verbal AI interaction model.

Reason for improvement

Real-time animation cut-off logic occasionally introduced small timing drift. Moving to a pre-aligned playback strategy improved visual smoothness and supported more natural-sounding voice output.

Architecture Decision Summary

The final stack combines the strongest validated components from all prototypes: robust form extraction, adaptive multi-turn conversational logic, and synchronized avatar interaction optimized for perceived naturalness.

Decision outcome: retain proven extraction and interaction primitives, remove brittle schema dependencies, and adopt playback-aligned speech synchronization for more stable user experience.
